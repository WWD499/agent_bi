# agent_bi 智能 BI 数据分析多步推理智能体平台 — 需求规格说明书

> 文档版本：v1.2 ｜ 编制：产品组 ｜ 适用范围：agent_bi 平台
> 说明：本文档基于已建成的真实系统撰写，所列能力均为已实现功能；凡涉及具体量化指标处均标注「估算」，未做精确计量。

---

## 一、需求概述

### 1.1 项目背景

企业在数字化转型中积累了大量业务数据（订单、客户、产品、营收、预警等），但业务人员普遍缺乏查询语句与数据分析能力，依赖技术人员排期取数——响应慢、链路长。本项目在原「AI 智能 BI 数据分析平台」业务层基础上，独立孵化出 **agent_bi** —— 一个以「对话即分析」为核心的多步推理智能体平台。

### 1.2 建设目标

- **对话式取数**：用户用自然语言提问，系统自动完成「理解意图 → 探查表结构 → 生成并执行查询语句 → 校验数据 → 选型图表 → 解读结论」的全过程。
- **推理轨迹可见**：智能体的每一步工具调用、中间推理、最终答案均以流式方式逐字推送给前端，过程透明、可审计。
- **业务知识融合**：内置检索增强知识库，将业务口径、指标定义前置消解语义歧义，降低「同词不同义」导致的错误查询。
- **安全可控**：只读查询经五层防护 + 表名白名单，杜绝写入与越权访问。

### 1.3 解决的核心痛点

| 痛点 | 本平台对策 |
|------|------------|
| 业务人员不会写查询语句 | 自然语言转查询工具自动生成并执行 |
| 取数依赖技术团队、链路长 | 对话即取数，秒级返回 |
| 不知道有哪些表/字段可用 | 数据表探查 / 字段探查工具自动列出 |
| 图表选型靠经验 | 智能图表选型按数据特征自动匹配 |
| 业务口径不清导致错数 | 知识库前置消解语义歧义 |
| 分析过程黑盒、不可信 | 流式暴露完整推理轨迹 |

### 1.4 适用范围

面向制造业/企业数字化场景的管理者、分析师、执行人三类角色，覆盖问数视图、智能分析报告、智能驾驶舱三类智能应用能力。

## 二、用户角色与权限

### 2.1 三类角色定义

| 角色 | 核心诉求 | 典型场景 |
|------|----------|----------|
| **管理者** | 全局概览、风险监控、资金动向 | 「本月订单趋势如何？哪些预警已触发？」 |
| **分析师** | 数据细节、供需对比、政策效果评估 | 「统计总订单数并按月拆分」「对比去年营收」 |
| **执行人** | 具体任务跟踪、项目进度、待办跟进 | 「查一下客户 X 的明细」「这条预警为什么触发？」 |

### 2.2 角色-功能权限矩阵

| 功能模块 | 管理者 | 分析师 | 执行人 |
|---------|:------:|:------:|:------:|
| 对话提问（入口） | ✅ | ✅ | ✅ |
| 数据表探查 / 字段探查 | ✅ | ✅ | ✅ |
| 自然语言转查询 / 安全执行 | ✅ | ✅ | ✅（限只读） |
| 业务知识检索 | ✅ | ✅ | ✅ |
| 智能图表渲染 | ✅ | ✅ | ✅ |
| 预警分析 | ✅ | ✅ | ✅ |
| 数据沙箱（导入/写表） | ✅ | ✅ | ✅ |
| 登录鉴权 | 必须 | 必须 | 必须 |

> 权限边界：所有角色默认仅能执行只读查询；锁定「数据沙箱」时可受限写入（建表/改表/导入/落表/删表），但需用户确认 + 审计，绝不触碰生产库；单轮工具调用上限 15 次，防止死循环。

## 三、业务功能需求

### 3.1 功能清单

| 编号 | 功能名称 | 一句话描述 |
|------|----------|-----------|
| F01 | 多步推理对话（智能体编排） | 自主规划、循环调用工具直至得出答案 |
| F02 | 数据表探查 | 列出业务库全部表名及备注信息 |
| F03 | 字段探查 | 列出指定表的字段名、类型和备注 |
| F04 | 自然语言转查询 | 将自然语言转为数据库查询语句并执行取数 |
| F05 | 安全查询执行 | 执行只读查询（五层防护 + 表名白名单） |
| F06 | 业务知识检索 | 从知识库中语义检索相关业务条目 |
| F07 | 智能图表选型 | 根据数据特征自动选择最佳图表类型并渲染 |
| F08 | 预警分析 | 判断预警规则是否触发、级别高低及原因解读 |
| F09 | 流式推理轨迹 | 实时推送每一步的思考过程和中间结果 |
| F10 | 用户登录鉴权 | 登录获取访问令牌，全局鉴权拦截 |
| F11 | 对话式创建与更新大屏 | Agent 调用 create_dashboard / update_dashboard 工具新建或更新 BI 大屏 |
| F14 | 数据沙箱（写工具） | 沙箱内建表/改表/导入/落表/删表 5 个写工具，需用户确认 + 自我修正 + 审计 |

### 3.2 逐条功能详述

#### F01 多步推理对话

- **输入**：用户自然语言问题 + 会话标识。
- **处理**：智能体构造系统提示词 + 加载历史记忆 + 十五项工具的能力描述清单（7 业务只读 + 5 沙箱只读 + 5 沙箱写工具 + 2 大屏工具），调用大模型；解析模型返回的工具调用指令，循环调用对应工具并将结果回填，直至模型判断可以给出最终答案时，以流式方式输出。
- **输出**：流式事件流（详见第六章接口协议）。
- **业务规则**：单轮工具调用不超过 15 次；异常时兜底返回摘要。

#### F02 数据表探查

- **输入**：数据源编号（默认使用第一个配置的数据源）。
- **处理**：根据数据源编号读取对应的动态业务库连接配置，连接目标库后查询全部可用表名及备注。
- **输出**：数据源编号、表数量、表列表（每项含表名和备注说明）。

#### F03 字段探查

- **输入**：数据源编号、目标表名。
- **处理**：连接指定数据源，查询目标表的全部字段元数据。
- **输出**：表名、字段数量、字段列表（每项含字段名、数据类型、备注说明）。

#### F04 自然语言转查询

- **输入**：用户的自然语言问题、数据源编号。
- **处理**：调用经过知识库增强的自然语言转查询服务——先从知识库检索相关业务口径定义消除歧义，再结合表结构信息生成查询语句并自动执行。
- **输出**：结构化结果（生成的查询语句 / 列定义 / 行数 / 推荐图表类型 / 图表名称 / 前 20 条样本数据 / 数据解读分析）。

#### F05 安全查询执行

- **输入**：数据源编号、待执行的查询语句。
- **处理**：先经安全校验器进行五层防护检查（语句类型 / 禁用关键词 / 注入特征 / 多语句 / 表名白名单），通过后由数据源工厂动态建立连接并执行只读查询。
- **输出**：查询结果（字段定义 + 数据行，最多返回 100 行）。
- **业务规则**：仅允许查询类语句；禁止写入/修改/删除/建删表等操作；拦截注入攻击和多语句执行；引用的表必须在白名单范围内。

#### F06 业务知识检索

- **输入**：检索关键词或自然语言问题、返回条数上限。
- **处理**：在知识库中进行向量语义相似度计算排序，同时辅以关键词模糊匹配作为兜底保障，合并去重后返回最相关的知识条目。
- **输出**：命中数量、知识条目列表（每项含编号、标题、正文摘要、所属业务领域）。

#### F07 智能图表选型

- **输入**：数据摘要（来自自然语言转查询或安全查询执行的返回结果）。
- **处理**：根据数据的列数、类型、行数等特征自动匹配合适的图表类型，并生成前端可直接使用的图表配置。
- **输出**：图表配置数据（前端直接渲染为可视化图表）。

#### 多图交错渲染（F07 扩展）

- **说明**：支持一次提问生成多张图表，文字与图表在对话中交错呈现。

#### F08 预警分析

- **输入**：预警规则编号。
- **处理**：调用预警规则分析服务，复用已有的检查执行/阈值比较/等级判定/异常分析等逻辑链路。
- **输出**：结构化结果（实际值 / 阈值 / 是否触发 / 告警级别 / 触发时的智能原因分析）。

#### F11 对话式创建与更新大屏

- **输入**：用户自然语言描述（新建大屏或向已有大屏追加图表）。
- **处理**：Agent 调用 `create_dashboard` 工具新建 BI 大屏，或调用 `update_dashboard` 工具向已有大屏追加图表；生成完成后返回可跳转打开的深链。
- **输出**：大屏创建/更新结果及深链。

#### F14 数据沙箱（写工具）

- **输入**：用户在沙箱内的建表 / 改表 / 导入 / 落表 / 删表 请求。
- **处理**：沙箱 5 个写工具执行前均需用户确认，并进入自我修正循环（≤3 次）直至通过；所有写操作写入 `bi_sandbox_audit` 审计表留痕。
- **输出**：写操作执行结果及审计记录。

## 四、非功能需求

| 类别 | 需求项 | 目标值（估算） |
|------|--------|---------------|
| 性能 | 流式首字延迟 | < 3 秒（依赖大模型网关响应速度） |
| 性能 | 单次工具调用耗时 | < 5 秒（查询/检索类操作） |
| 性能 | 并发对话能力 | 虚拟线程异步处理，单实例可支撑数十路并发 |
| 可用性 | 推理轨迹实时性 | 工具调用、思考过程、答案生成均逐字流式推送 |
| 安全 | 只读约束 | 五层查询安全校验 + 表名白名单，零写入能力 |
| 安全 | 身份鉴权 | 未登录用户访问业务接口一律返回未授权错误 |
| 安全 | 密钥管理 | 大模型密钥存储于运行环境变量，不写入任何文件或数据库 |
| 可扩展性 | 工具扩展机制 | 统一工具接口规范，新增工具只需实现四个标准方法即可接入 |
| 可观测性 | 异常兜底 | 任意步骤失败时推送错误事件 + 兜底摘要，系统不崩溃 |
| 兼容性 | 前端技术栈 | 独立构建部署，支持亮色/暗色双主题切换 |

## 五、数据需求

### 5.1 数据存储分层

| 数据类别 | 存储方式 | 说明 |
|----------|----------|------|
| 系统库（用户/权限/平台元数据） | PostgreSQL | 含数据源配置表、知识库表、预警相关表等 |
| 业务数据源（动态接入） | MySQL | 通过数据源配置表动态对接，示例库含订单/客户/产品/月营收等表 |
| 向量索引（知识库嵌入） | PostgreSQL + 向量扩展 | 知识库正文的向量表示（1024 维），用于语义检索 |
| 会话记忆 | 应用内存（可替换为 Redis） | 按会话标识索引的消息队列，保留最近 10 轮对话 |

### 5.2 关键数据表

- **数据源配置表**：记录动态业务数据源的连接参数（类型/地址/端口/库名/账号/密码/启用状态）。
- **知识库表**：存储业务知识条目及其向量表示。
- **预警规则表 / 预警配置表 / 预警记录表**：分别存储预警规则定义、调度状态跟踪、历史告警事件。

## 六、接口需求

### 6.1 登录接口

- **请求方式**：POST（登录接口路径）
- **请求参数**：用户名和密码（均为必填）
- **返回结果**：成功时包含访问令牌和用户名

### 6.2 流式推理接口

- **请求方式**：POST（对话接口路径），携带访问令牌
- **请求参数**：用户问题文本 + 会话标识
- **返回格式**：流式事件流，事件协议如下：

| 事件类型 | 触发时机 | 内容说明 |
|----------|----------|----------|
| 工具调用 | 智能体决定调用某个工具 | 包含工具名称和参数 |
| 工具结果 | 工具执行完毕返回 | 包含工具名称和返回结果 |
| 思考过程 | 大模型的中间推理文本 | 纯文本片段 |
| 答案片段 | 最终答案逐字生成 | 纯文本片段 |
| 图表 | select_chart 生成的图表渲染块 | 对话中直接渲染图表，与文字交错呈现 |
| 结束标记 | 整次推理流程结束 | 空内容 |
| 错误事件 | 任意步骤发生异常 | 错误描述文本 |

## 七、约束与假设

### 7.1 技术约束

- **运行环境要求 Java 21**：框架强制依赖虚拟线程特性，启动脚本已固定指向 Java 21 运行环境，低版本将无法启动。
- **采用手写推理编排而非 AI 框架**：因现有 AI 开发框架在本环境存在核心组件缺失问题，故改为基于原生大模型调用的手写推理循环，零新增外部依赖。
- **大模型服务接入**：通过统一大模型网关 `https://ai-api-prod.qingjiao.art/v1`（OpenAI 兼容协议，本项目用 deepseek-v3，向量化用 BAAI/bge-m3）接入；密钥仅存于运行环境变量（ARK_API_KEY）。

### 7.2 环境假设

- 缓存服务未部署时会话记忆走内存模式，生产环境可平滑切换至缓存实现。
- 业务数据库需预先在数据源配置表中登记并启用。
- 前端工程通过开发代理转发请求到后端服务，登录后自动携带访问令牌。
