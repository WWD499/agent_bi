## 一、环境要求

### 1.1 必需环境

| 环境 | 要求版本 | 用途 |
|------|----------|------|
| Java JDK | **21 或以上**（必须，不支持 Java 8/11/17） | 后端运行时 |
| Maven | 3.8+ | 项目构建（后端） |
| Node.js | 18+（推荐 22） | 前端工程依赖管理与构建 |
| npm | 9+（随 Node.js 安装） | 前端包管理 |
| PostgreSQL | 15+ | 系统数据库 + 向量检索扩展 |
| pgvector 扩展 | 0.5+ | 向量相似度计算（知识库检索必需） |
| MySQL | 8.0+ | 业务数据源（动态接入） |

### 1.2 可选环境

| 环境 | 说明 |
|------|------|
| Redis 5+ | 会话记忆持久化。不部署时使用内存存储（重启丢失会话历史） |
| PaddleOCR 服务（Python FastAPI） | OCR 文档识别功能的后端服务。不部署则 OCR 相关功能不可用 |

### 1.3 外部依赖服务

| 服务 | 是否必需 | 说明 |
|------|----------|------|
| 大模型 API 网关（OpenAI 兼容协议） | ✅ 必需 | 推理能力来源。需要有效的 API 密钥 |

## 二、后端部署

### 2.1 构建步骤

```bash
# 进入后端工程目录
cd bi-agent-platform

# 使用 Maven 打包（跳过测试加速）
bash mvn clean package -DskipTests

# 构建产物位置：target/agent-bi-platform.jar
```

> ⚠️ **注意**：在 Git Bash 环境下执行 Maven 时，请使用 `bash mvn` 而非直接 `mvn`，以避免 Windows 路径兼容问题。

### 2.2 启动方式

#### 方式一：使用启动脚本（推荐）

```bash
# 设置大模型 API 密钥（必需）
export ARK_API_KEY="你的API密钥"

# 运行启动脚本
bash run.sh
```

启动脚本已内置以下逻辑：
- 自动查找 Java 21 运行时（优先从 `JAVA_HOME` 环境变量读取，否则回退到预设路径）
- 默认监听端口：**8080**
- 支持通过命令行参数覆盖端口：`bash run.sh --server.port=9090`

#### 方式二：手动启动

```bash
java -jar target/agent-bi-platform.jar --server.port=8080
```

### 2.3 配置说明

核心配置文件位于 `src/main/resources/application.yml`：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 服务端口 | HTTP 监听端口 | 8080 |
| 数据库连接 | PostgreSQL 连接地址/库名/账号/密码 | 需按实际修改 |
| 大模型网关地址 | OpenAI 兼容 API 端点 | 需配置 |
| API 密钥 | 通过环境变量 `ARK_API_KEY` 传入 | 无默认值 |
| 令牌头名称 | Sa-Token 鉴权使用的请求头名称 | satoken |
| 向量维度 | 嵌入模型输出向量维度 | 1024（对应 bge-m3） |

**安全提醒**：API 密钥请勿直接写入配置文件或代码中，始终通过环境变量传递。

### 2.4 健康检查

服务启动完成后，可通过以下接口验证运行状态：

```
GET http://localhost:8080/actuator/health
```

正常返回：`{"status":"UP"}`

## 三、前端部署

### 3.1 构建步骤

```bash
# 进入前端工程目录
cd agent-ui

# 安装依赖（首次运行需要）
npm install

# 开发模式启动（热更新，适合调试）
npm run dev
# 访问地址：http://localhost:5173

# 生产构建（产出静态文件）
npm run build
# 构建产物位置：dist/ 目录
```

### 3.2 开发代理配置

开发模式下，Vite 内置代理将前端的 `/api` 请求自动转发到后端：

```
前端请求 /api/* → 代理转发 → http://localhost:8080/api/*
```

无需额外配置跨域问题。

### 3.3 生产部署

生产构建后的 `dist/` 目录为纯静态文件，可部署到任意 Web 服务器（Nginx/Apache/Tomcat 静态资源目录）。需确保反向配置将 `/api` 路径转发到后端服务。

## 四、数据库初始化

### 4.1 PostgreSQL 系统库

#### 建库与扩展

```sql
-- 创建系统数据库（如不存在）
CREATE DATABASE ry;

-- 连接到该库后启用向量扩展
CREATE EXTENSION IF NOT EXISTS vector;
```

#### 业务表初始化

系统启动时会自动创建所需的业务表（通过初始化 SQL 脚本）。涉及的表包括：
- `bi_datasource` — 数据源配置表
- `bi_knowledge` — 知识库表（含向量字段）
- `bi_alert_rule` / `bi_alert_config` / `bi_alert_record` — 预警相关表

> 完整的表结构定义（字段类型/约束/索引）详见《数据库设计说明书》。

### 4.2 MySQL 业务数据源

MySQL 作为动态接入的业务数据源，不需要预先建表——系统通过数据源配置表中的连接参数按需连接。

但你需要确保：
1. MySQL 服务可达（网络/防火墙允许连接）
2. 在 `bi_datasource` 表中正确配置了连接信息并标记为"启用"
3. 配置的账号对该库有只读查询权限（符合最小权限原则）

### 4.3 示例数据

项目附带示例业务数据的初始化脚本（`_seed_ds.sql`），包含演示用的订单/客户/产品/月营收表及样本数据，可用于功能验证。

## 五、运维操作指南

### 5.1 日常检查

| 检查项 | 方法 | 正常标志 |
|--------|------|----------|
| 后端服务状态 | 访问 `/actuator/health` | 返回 `{"status":"UP"}` |
| 前端页面可访问 | 浏览器打开前端地址 | 登录页正常加载 |
| 数据库连接 | 执行一次对话查询 | 能正常返回结果 |
| 大模型可用性 | 提交一个简单问题 | 能收到推理回复 |

### 5.2 日志查看

- 后端日志输出到控制台（标准输出），启动脚本未重定向到文件
- 关键日志关键字：`AgentChatController`（对话入口）、`BiAgentService`（推理循环）、`LlmService`（大模型调用）、`SqlValidator`（安全校验）
- 如需持久化日志，可在启动命令追加日志重定向：`bash run.sh >> app.log 2>&1 &`

### 5.3 常见问题处理

| 现象 | 可能原因 | 解决方法 |
|------|----------|----------|
| 启动报 `UnsupportedClassVersionError` | Java 版本低于 21 | 确认 `java -version` 显示 21+；或检查启动脚本中的 Java 路径 |
| 全部接口返回 401 | 令牌头配置冲突 | 确认配置文件中令牌头名称为 `satoken`，前端传参不含 `Bearer` 前缀 |
| 对话请求超时无响应 | 大模型网关不可达或密钥无效 | 检查网络连通性；确认 `ARK_API_KEY` 环境变量已设置且有效 |
| 知识库检索无结果 | pgvector 扩展未安装或向量维度不匹配 | 确认 PostgreSQL 已安装 pgvector 扩展；确认嵌入模型维度为 1024 |
| 前端代理报错 502 | 后端未启动或端口不一致 | 确认后端已在 8080 端口启动 |
